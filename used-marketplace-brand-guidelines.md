# Used Marketplace Brand Guidelines

## 1. Purpose of this document
This document defines the working brand direction for the Used Marketplace project so the UI stays consistent from the beginning of design and development. It focuses on visual consistency, trust, clarity, and a clean marketplace experience, with priority given to the authentication screens in the current phase.

---

## 2. Brand purpose
The platform is a used-product marketplace. The brand must communicate:
- trust
- simplicity
- clarity
- safety
- practical usability
- modern digital experience

A user should feel that the platform is:
- reliable enough to register
- easy enough to use without confusion
- professional enough to trust with account creation and buying/selling activity

---

## 3. Brand personality
The product should feel:
- clean
- modern
- confident
- helpful
- secure
- calm

It should **not** feel:
- cluttered
- overly playful
- visually noisy
- too corporate and cold
- complicated

The visual direction should support a second-hand marketplace that feels safe and organized, not chaotic.

---

## 4. Core brand values
1. **Trust**  
   The user must feel comfortable creating an account and interacting with sellers or buyers.

2. **Clarity**  
   Information should be easy to scan, and the interface should not overwhelm the user.

3. **Simplicity**  
   Core tasks should feel straightforward: create account, log in, browse, list an item, message, and make offers.

4. **Consistency**  
   Repeated UI elements should behave and look the same everywhere.

5. **Efficiency**  
   The platform should feel lightweight and practical, especially on mobile.

---

## 5. Audience impression
When a new user lands on the product, the first impression should be:

- this platform looks real
- this platform is safe to use
- this platform is modern
- this platform is easy to navigate
- this platform is designed for buying and selling used items clearly

This impression matters most on the login and registration pages, because that is where trust is first tested.

---

## 6. Tone of voice
The product writing should be:
- short
- direct
- friendly
- professional
- non-technical

Examples of correct tone:
- Create your account
- Welcome back
- Verify your email to continue
- Please enter a valid email address
- Your username is already taken
- Check your inbox for the verification link

Avoid:
- long robotic sentences
- overly technical wording
- unclear error messages
- playful jokes in important auth flows

---

## 7. Visual direction
The interface should follow these principles:

### 7.1 Clean layout
Use a lot of structure and spacing. Avoid cramped forms and dense content blocks.

### 7.2 Strong hierarchy
The eye should move clearly from:
- title
- supporting text
- main action area
- secondary actions
- feedback state

### 7.3 Calm visual rhythm
Use spacing, card layouts, and soft surfaces to make the UI feel controlled and trustworthy.

### 7.4 Minimal noise
Decorative elements should support the product, not distract from its purpose.

---

## 8. Color strategy

### 8.1 Primary color
Use one stable primary brand color for:
- main buttons
- active states
- links
- focus accents
- highlighted actions

A strong primary color should communicate trust. Good directions include:
- deep green
- blue
- teal

### 8.2 Secondary color
Use a secondary tone only for support, not competition with the primary action. It can be used for:
- soft backgrounds
- badges
- light accents
- empty state illustrations

### 8.3 Neutral system
The product needs strong neutral colors for:
- page background
- card surfaces
- borders
- body text
- muted text
- input backgrounds

### 8.4 Semantic colors
Use dedicated colors for:
- success
- warning
- error
- info

They should be visually clear but not over-saturated.

### 8.5 Auth-specific rule
On login and signup screens, the primary button color should be consistent and should always be the most visually important action.

---

## 9. Typography

### 9.1 Font behavior
Use a clean modern font with:
- strong readability
- good number rendering
- good mobile legibility
- clear hierarchy

### 9.2 Typography hierarchy
At minimum, define:
- page title
- section heading
- body text
- label text
- helper text
- error text
- caption text

### 9.3 Auth screens hierarchy
For login and signup pages, the order should be:
1. page title
2. supporting line
3. form labels and fields
4. submit button
5. alternate action link

---

## 10. Spacing system
The interface should use a consistent spacing scale.
The same distances should repeat across:
- page sections
- fields
- labels
- helper text
- card padding
- button groups

Spacing should make the product feel thoughtful and structured.

### Auth page rule
Forms should never feel crowded. Use enough vertical spacing between fields and between the form and the title.

---

## 11. Buttons

### 11.1 Primary button
Used for the main action:
- Sign up
- Log in
- Continue
- Save

### 11.2 Secondary button
Used for lower-priority actions:
- Cancel
- Back
- Skip

### 11.3 Button consistency
Buttons should keep the same:
- radius
- height
- font weight
- loading behavior
- disabled behavior
- hover behavior

---

## 12. Inputs and form fields

### 12.1 Required consistency
All inputs should follow the same style rules for:
- border
- background
- focus state
- placeholder
- error state
- helper text

### 12.2 Password fields
Password fields should support:
- show/hide password toggle
- clear error indication
- good spacing for helper text

### 12.3 Auth feedback states
Field-level feedback should be clear for:
- missing input
- invalid input
- duplicate username
- duplicate email
- wrong credentials

---

## 13. Card and surface design
Cards should feel:
- clean
- soft
- readable
- structured

Use cards for:
- auth forms
- future listing summaries
- future notifications
- dashboard info blocks

The auth screens should ideally use one central card containing the main form.

---

## 14. Iconography
Icons should be:
- simple
- recognizable
- consistent in stroke or fill style
- used to support meaning, not decoration only

Examples:
- email
- password visibility
- user account
- success state
- warning state

Do not overuse icons in forms.

---

## 15. Imagery
If imagery is used, it should support trust and usefulness.
For the early auth phase, keep imagery light and optional.

Good usage:
- subtle side illustration
- simple marketplace-themed hero graphic
- placeholder brand graphic

Avoid:
- busy stock photos
- distracting background images
- anything that reduces readability

---

## 16. Auth page brand rules

### 16.1 Login page should communicate
- welcome back
- safety
- simplicity
- fast access

### 16.2 Signup page should communicate
- easy onboarding
- trust
- low friction
- clear next step

### 16.3 Verify Email page should communicate
- progress
- reassurance
- clear instruction
- next action

### 16.4 Error page should communicate
- calm feedback
- not panic
- easy recovery path

---

## 17. Responsiveness
The brand experience must remain strong on:
- desktop
- tablet
- mobile

For auth pages:
- the form should remain centered or well-anchored
- field sizes should stay comfortable on small screens
- button tap size should remain usable
- spacing should not collapse too tightly

---

## 18. Accessibility and usability standards
Design should support:
- high text readability
- visible focus states
- sufficient contrast
- easy-to-read error messages
- clear label/field relationships
- large enough tap targets

Accessibility should not be treated as optional. It directly affects trust and usability.

---

## 19. Product consistency rules
Across the app, the following must remain consistent:
- corner radius system
- button styling
- text hierarchy
- spacing rhythm
- border color logic
- form behavior
- error display style

This is important because the marketplace will grow into listings, messaging, offers, and admin tools. Visual inconsistency will make the product feel unfinished.

---

## 20. Working brand direction for current phase
For the current login and registration phase, the UI should feel:

- trustworthy
- modern
- minimal
- clean
- soft but not weak
- professional without looking boring

The auth pages should be visually strong enough that a user feels comfortable creating an account immediately.

---

## 21. Deliverables designers should eventually define
To fully finalize the brand system, designers should provide:
- color palette
- type scale
- button variants
- input variants
- spacing scale
- icon usage rules
- auth page layouts
- mobile layout adaptations
- card styles
- semantic colors for success, warning, and error

---

## 22. Summary
The Used Marketplace brand should balance trust, simplicity, and clarity. The product must feel safe enough for registration and practical enough for daily marketplace use. Every visual decision should support usability first, with a calm and modern appearance that can scale across authentication, listings, messaging, offers, and other future product areas.
